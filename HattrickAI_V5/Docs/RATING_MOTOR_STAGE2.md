# Rating Motor Stage 2 — Raw → Displayed Rating

## Status

**Implemented on `v5`.**

Stage 1 established formation-aware position semantics. Stage 2 now isolates the conversion from a sector's raw contribution ledger to the displayed Hattrick regional rating.

## Conversion model

The implementation uses the researched HO Organizer structure:

```text
scaled = raw × sectorScale
Displayed = clamp(round(pow(scaled, 1.2) / 4 + 1, 2), 1, 20)
```

Sector scales:

| Sector | Scale |
|---|---:|
| Left Defence | 0.834 |
| Central Defence | 0.501 |
| Right Defence | 0.834 |
| Midfield | 0.312 |
| Left Attack | 0.615 |
| Central Attack | 0.513 |
| Right Attack | 0.615 |

These values are a **community/reverse-engineered HO reference**, not claimed official Hattrick source code.

## Architectural boundary

The seven `Raw*` fields remain raw contribution values. Displayed fields are generated by `HattrickRatingDisplayConverter` and are therefore no longer a disguised rounding of the raw ledger.

`Stage2RegionalRatingEngine` wraps the existing base engine, while `Stage2RegionalRatingEngineFixed` wraps the current fixed/live engine. This keeps Stage 2 isolated: contribution coefficients can now be rebuilt in later stages without changing the raw-to-display mathematics.

The M7 scenario layer, Motor 2 opponent-aware refinement and Motor 3 behaviour-rating path now use the Stage 2 adapters.

## Regression

`Stage2RatingDisplayRegression` verifies:

- zero raw contribution maps to rating 1;
- sector-specific scales produce different displayed values;
- the raw ledger is preserved unchanged;
- known raw=10 reference outputs are stable.

Reference outputs for raw = 10:

- Midfield: 1.98
- Central Defence: 2.73
- Left/Right Defence: 4.19
- Central Attack: 2.78
- Left/Right Attack: 3.21

## Known limitation / next stage

Stage 2 deliberately does **not** retune the contribution coefficients. The existing V5 raw contribution layer was originally producing display-like values directly. After this structural separation, the remaining gap must be solved in Stage 3+ by rebuilding the skill normalization and contribution ledger against the researched HO model and CAL fixtures, not by adding another display calibration multiplier.
